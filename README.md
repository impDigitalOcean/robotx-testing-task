# robotx-testing-task
## Текст задачи
Российская компания решила перевести управление своими клиентами из старой учетной системы в новую, основанную на базе данных MS SQL. 
Программисты сделали выгрузку всех клиентов в XLSX файл. Данные выгружены "как есть".

## Задача. 
Написать программу, которая позволяет: 
1. Импортировать Excel-файл в базу данных, приведя данные к необходимому типу
2. Посмотреть данные из БД в каком-нибудь гриде, отредактировать какое-либо поле и записать изменения в БД. 
3. Возможность обновления данных через новый Excel-файл (*в задании написано XML-файл, опечатка? везде упоминается Excel кроме доп задания*)

## Запуск

### 1. Настройка строки подключения
Перед первым запуском указать строку подключения в проекте:

- `ImportedDatabaseViewer/appsettings.json` → `ConnectionStrings:DefaultConnection`

### 2. Далее, запуск проекта
```
dotnet run --project ExcelDatabaseImporter
```

и

```
dotnet run --project ImportedDatabaseViewer
```

## Результат
Решение состоит из двух проектов, использующих общую БД MS SQL:

### ClientsImporter (консольное приложение)
- Читает XLSX, приводит данные к типам:
  - Даты: `DateTime.TryParse` с культурой `ru-RU`, некорректные даты логируются и пропускаются
  - Числа: `int.TryParse` с `DBNull` для пустых ячеек
  - Текст: `SqlDbType.NVarChar` (кириллица сохраняется)
- Идемпотентный импорт (UPSERT по `CardCode`):
  - Существующие - `UPDATE` всех полей кроме `CardCode`
  - Новые - `INSERT`
  - Дубли внутри файла - обрабатываются (последняя строка выигрывает)
- Весь импорт в одной транзакции
- Сводка после импорта: вставлено, обновлено, пропущено, ошибок

### ImportedDatabaseViewer (ASP.NET MVC)
- Грид с клиентами (`/Clients`), серверная пагинация (OFFSET/FETCH, 25 на страницу)
- `UPDATE` параметризованный, без SQL-инъекций
- `TempData` для баннеров об успехе/ошибке
- Номер страницы сохраняется при редиректе после сохранения
- Валидация через DataAnnotations + `ModelState.IsValid`

### Строка подключения
`appsettings.json` - `ConnectionStrings:DefaultConnection` в каждом проекте.

### Известные ограничения
- `OFFSET` деградирует на глубоких страницах (для 30k записей не критично; в проде - keyset pagination)
- Нет поиска и сортировки по колонкам
- Секреты в `appsettings.json` (для тестового допустимо)
- Строка подключения для импортёра вводится интерактивно - для тестового задания это удобнее, чем appsettings.json (можно указать произвольную БД без правки файлов). В проде - общий конфиг или переменные окружения.
